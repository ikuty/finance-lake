# 書類本体ダウンロード時のストレージ容量試算（2026-08-25）

対象を「ウォッチリスト企業のみ」から「`secCode IS NOT NULL`（上場企業）全件」に拡大した際、
`/home`配下の500GB HDDに収まるかを実測データに基づいて再確認した記録。

## 方法

1. EDINET書類一覧API（`type=2`）を過去1年分（2025-08-26〜2026-08-25、365日）、
   実際に1.2秒間隔で呼び出し、`secCode`が設定されている書類の件数を`docTypeCode`別に集計した。
2. 主要な`docTypeCode`について、実際に書類取得API（`type=1`XBRL・`type=2`PDF・`type=5`CSV化XBRL）
   を呼び出し、3形式合計の実ファイルサイズをサンプリングした。
3. 件数×平均サイズで年間・10年分のデータ量を試算した。

## 試算結果

| 区分 | 年間小計（概算） |
|---|---|
| 有価証券報告書（120） | 約12.4 GB |
| 訂正有価証券報告書（130、120と同等と仮定） | 約2.0 GB |
| 半期報告書・訂正半期報告書（160・170） | 約1.0 GB |
| その他（135/180/220/235/未実測26種、030含む） | 約0.8〜2.1 GB |
| **合計** | **約17.3〜18.7 GB/年** |

**10年分で約173〜187 GB。500GB HDDに対し2.7倍程度の余裕がある。**

有報の平均サイズは小型・中型・大型企業3社をサンプリングした値であり、最大の寄与要因
（全体の約72%）についてはある程度の代表性があると考えられる。この試算が3倍近く外れない
限り、容量超過は起きない見込み。

## 結論

対象を「ウォッチリスト企業のみ」から「全上場企業」に拡大しても、500GB HDDへの生ファイル
保存で問題ない。ウォッチリスト機能は不要と判断し、`secCode IS NOT NULL`によるフィルタのみ
を対象条件とする。

## 補足: 過去の見積もりとの関係

以前（VPS/S3検討時）に使用した「313GB」という数値とは前提（対象範囲・時期）が異なるため
単純比較はできない。本試算は全上場企業・実測データに基づく、現時点で最も信頼性の高い数値。
